## 4. Proposal

### A. One pure definition (new file, so no shared-file edits for the logic)
`PixelSwitch/Models/AccountPlan.swift` (pure Foundation; must be added to the file list in `Tests/run-unit-tests.sh`; the app target picks it up automatically; the CLI target does NOT include it, see gotcha 7):

```swift
enum AccountPlan: Equatable, Sendable {
    case pro, max5x, ultra          // ultra = Max 20x
    case other(String)              // any other subscriptionType (team, enterprise, ...)
    case unknown                    // nothing known
    static func resolve(subscriptionType: String?, planTier: String?,
                        planDisplayName: String? = nil) -> AccountPlan
    var hasSessionLimit: Bool { if case .ultra = self { return false }; return true }
    func badgeText(subscriptionType: String?) -> String?   // "Ultra", else today's capitalised string
}
```
- `.ultra` iff (tier is `max_20x` or `default_claude_max_20x`, or `planDisplayName` equals "ultra", case-insensitive, trimmed) AND `subscriptionType` is nil or "max". **Unknown / nil / unrecognised -> `hasSessionLimit == true` (keep the 5-hour limit).**
- `Account` gains ONE stored property `var planTier: String?` (optional `var` = no init change; nil is omitted when encoded, old saved accounts decode as nil) and computed `plan`, `hasSessionLimit`. **`displaySubscriptionType` (`Account.swift:61-63`) becomes `plan.badgeText(...)`: this one edit turns every badge into "Ultra" (popover header orange badge, Usage card badge, Accounts-list text, CLI/MCP `subscription`, widget).** The badge text therefore comes from the same single place as `hasSessionLimit`.
- `AuthStatus` gains `var planTier: String?` (`Account.swift:148-155`). Must be `var` with an optional type, NOT `let`: `Tests/UnitTests/SignInTests.swift:119` builds `AuthStatus(...)` with the memberwise init and would stop compiling.
- Filling `planTier`: (1) copy `status.planTier` at the four sites where `subscriptionType` is copied (`AppState.swift:293/305, 538, 633, 2298/2310`); (2) a pure parser `AccountPlan.tier(fromCredential:oauthAccount:)` (credential `claudeAiOauth.rateLimitTier`, else `oauthAccount.organizationRateLimitTier`, plus `planDisplayName`) used to backfill the other accounts from `keychain.getAccountBackup(forAccountId:)` once after `loadAccounts` (`AppState.swift:2239`) and after each capture (`noteCredentialChanged`). Without the backfill, the six non-active accounts stay "unknown" (so keep the 5-hour limit) until each becomes active; the data-driven path below still hides their rows in the meantime.
