# PixelSwitch 2.0: build lanes

Status: CURRENT. Written 2026-10-24 by the orchestrating session. The contract is
`docs/superpowers/specs/2026-10-24-2.0-spec.md` (revision 3); this file says who builds which part, in which files, in
which order. Builders are Sonnet (`sonnet-builder`), reviewers are Opus. At most two build lanes run at once on the
founder's Mac (his resource-warden rule).

## Order

| Wave | Lane | Builds | Depends on |
|---|---|---|---|
| 0 | V | `Tests/conformance/autoswitch-vectors.json` and its README: the executable form of spec sections 2, 3 and 6 | spec rev 3 |
| 1 | MA | Mac engine, models, settings readers, AppState rules, D12, D20, renewal fix, conformance harness, tests | V |

| 2 | LB | Linux daemon: Claude Code login files, saved logins, HTTP client, switch, capture, renewal, auto-switch cycle, sign-in, control server, updater IO, mock API, scratch-HOME integration on the laptop | LA merged |
| 3 | LC | Linux faces and shipping: CLI, MCP, tray, settings window, launchers, systemd unit, desktop files, icon, install.sh, build-release.sh, CI jobs, verify-release.sh | LB merged (protocol from LA) |

After each wave merges into `release-2.0`, Opus reviews that wave's diff (several lenses, read-only) and Sonnet fixes
what they find until zero P0 and zero P1 are open. Reviewers never run beside a builder of the same files.

## Rules every lane follows

- Work only in your worktree (the path is in your launch brief) on your lane branch, and only in the files your lane
  owns below. Commit on your branch with `git -c user.name=BespokeWoodcraftStudio commit`, messages ending with
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never push, merge, rebase onto main, stash, tag or touch
  another worktree. Never edit `.pbxproj` or `Info.plist`; never bump versions (the release script does).
- Never touch the PixelDirector repository or run `pixeldirector` (founder, 2026-10-24).
- Never install, upgrade or relink anything on the founder's machines (no `brew install`, `pip install` into a
  system or Homebrew Python, `npm -g`, apt). On 2026-10-24 a lane's `brew install pygobject3` pulled in python@3.15 and
  made it the default `python3`, which the orchestrator had to undo. Use `uv run --with` or a throwaway venv under the
  scratchpad, or report that a check needs a tool.
- Read the spec in full first, then the recon reports it cites for your part. The spec wins over the recon and the
  code; if they disagree in a way that matters, stop that item and report it.
- `Tests/conformance/autoswitch-vectors.json` is read-only for every lane after V. A case you believe is wrong is
  reported with your reasoning, never edited.
- Test first where the spec names a test. Run only the checks your lane names, after your last edit, and paste their
  final lines in your report.
- Anything you start (a server, a daemon, a browser, a test runner, a process on the laptop) is stopped before you
  report, and you say so.
- Report in at most 40 lines: what you built (files), check results (pasted), what you could not do and why, anything
  the orchestrator must decide.
