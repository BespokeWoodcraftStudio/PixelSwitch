## 2. Feature A: separate session (5-hour) and weekly (7-day) thresholds

### 2.1 Data

- `Account` gains `sessionThreshold: Double?` and `weeklyThreshold: Double?` (Swift `var`, optional, decode-safe).
  Whole numbers 1-100; `nil` = follow the next layer.
- `switchThreshold` keeps its meaning: both windows 1-100, `0` = Manual only, `nil` = follow the default.
- Global (Mac `UserDefaults`; Linux `settings.json`): existing `autoSwitchThreshold` (base, 50-100, unset = 90) plus
  `autoSwitchSessionThreshold` and `autoSwitchWeeklyThreshold` (50-100). **A global window key counts as set only when
  present and a finite number**: on the Mac `UserDefaults.object(forKey:) as? Double`, never `double(forKey:)` (which
  reads 0 for a missing key); on Linux the key is present and numeric. Absent, null, 0 or non-finite all mean follow the
  base. While its key is absent each Settings slider shows the effective value, never `fallbackThreshold`. (Test: with
  only `autoSwitchThreshold = 98` stored, both effective defaults read 98 and `settings.get` returns 98 for both new keys.)
- **Splitting the single value.** Before any per-window write (a Session or Weekly menu choice other than Manual only,
  Default included; `accounts.setThresholds` with a number or null; CLI `--session`/`--weekly`), if the account's
  `switchThreshold` is 1-100, copy it into each of `sessionThreshold`/`weeklyThreshold` that is nil, set
  `switchThreshold` to nil, then apply the write. So Default / null / `default` always means the global window
  default. (Test and vector: switchThreshold 70, Session set to Default: session = defaults.session, weekly = 70,
  switchThreshold = nil.)
- Only a number clears Manual only: a window number on a Manual only account clears Manual only, sets that window, and
  the other window follows its default; null (Default) on a Manual only account changes nothing.

### 2.2 Resolution (one pure function per platform)

```
base             = autoSwitchThreshold, unset or 0 -> 90, else clamp 50..100
defaults.session = clamp50to100(globalSession if set else base)
defaults.weekly  = clamp50to100(globalWeekly  if set else base)

rule(account).manualOnly = normalizedBoth(account.switchThreshold) == 0
rule(account).session = manualOnly ? 0 : (window(account.sessionThreshold) ?? both(account.switchThreshold) ?? defaults.session)
rule(account).weekly  = manualOnly ? 0 : (window(account.weeklyThreshold)  ?? both(account.switchThreshold) ?? defaults.weekly)

leaveAt(active).session = rule.session > 0 ? rule.session : defaults.session   (Manual only leaves at the defaults)
leaveAt(active).weekly  = rule.weekly  > 0 ? rule.weekly  : defaults.weekly
```

`window(v)`: not a finite number -> nil; else round half away from zero; a result <= 0 -> nil (follow the next layer);
above 100 -> 100. `both(v)`: today's `normalizedAccountThreshold` (0 = Manual only, 1-100), used only when non-zero.

### 2.3 Engine rules (replacing the single binding threshold; everything else in `AutoSwitchEngine` is unchanged)

`s`, `w`, `f` are a reading's session, weekly and Fable utilisation after the existing expiry rule, applied to all
three alike (a window whose `resets_at` is past is dropped; strict on the active side when the sample is retained,
lenient for candidates). `ceiling(t, room)` is the existing function (nil when `t <= 0`).

1. **Trigger, windows.** The active account reaches its limit when `s >= leaveAt.session` OR `w >= leaveAt.weekly`
   (a missing window cannot trigger). The window that fired is named (`session` first if both) in logs and in the
   `autoSwitched` event's new `window` field; `limit` stays `"windows"`.
2. **Trigger, Fable** (Fable watching on): `f >= leaveAt.weekly`.
3. **Candidate, threshold rule, on windows:** `cs = ceiling(rule.session, hysteresis)` and `cw = ceiling(rule.weekly,
   hysteresis)` must both be non-nil; the candidate needs at least one usable window reading, and every usable window
   reading must be under its ceiling (`s <= cs` if s known, `w <= cw` if w known). No reading at all: not eligible.
4. **Candidate on Fable:** `f <= cw` AND rule 3.
5. **Early drain and no-subscription:** as today, with `room = drainMinimumRoom` per window
   (`s <= ceiling(rule.session, 1)`, `w <= ceiling(rule.weekly, 1)`); the drain's Fable check uses the weekly ceiling.
6. **Room** (most room): on windows `min(rule.session - s, rule.weekly - w)` over the windows with a reading; on Fable
   `rule.weekly - f`. `keepsFable` = f known AND `f <= ceiling(rule.weekly, hysteresis)`; false when f is unknown.
7. Ranking for `mostRoom` and `resetsSoonest` is unchanged except for room from rule 6; `myOrder` (Priority) is the
   candidates' order, which is the priority-sorted accounts order. The tie-break in every strategy is that order.
8. **Equivalence (hard test):** when every account's session and weekly rules are equal AND
   `defaults.session == defaults.weekly`, every plan is identical to 1.9's. The engine checks in
   `Tests/UnitTests/AutoSwitchRulesTests.swift` and `Tests/UnitTests/main.swift` compile and pass unchanged through
   compatibility overloads that take one threshold per account (mapped to equal windows) for every engine entry point
   the tests call (`plan`, `rankedTargets`, `eligibleUtilization`, `drainEligibleUtilization`). Those overloads are for
   tests only: no non-test file may call them (a grep in section 7 acceptance proves it).
9. **Weekly overflow (D19).** Let `strict` be the plan computed with the rules above. If `strict` is nil and overflow
   holds, compute `relaxed`: the same plan with every account's weekly rule (and `defaults.weekly`) replaced by
   `max(weekly, session)` (Manual only stays Manual only). The result is `strict ?? relaxed`. **Overflow holds** when the
   active account (unless it has no subscription) and every candidate that is switchable, usable and not Manual only
   have a known weekly reading, and each is past its own strict weekly limit (active: `w >= leaveAt.weekly`; candidate:
   `w > ceiling(rule.weekly, hysteresis)`). With equal rules `relaxed == strict`, so rule 8 still holds. A switch made
   by the relaxed plan logs "every account is past its weekly limit, so the session limit decides". (This is why a drain
   or threshold move can never land on an account past its strict weekly limit while another account is still under
   it: that would ping-pong with rule 1 after the cooldown.)
10. **AppState (and the Linux coordinator) call only the two-window entry points.** `plan` receives each account's
    resolved `{session, weekly, manualOnly}` from 2.2 and the defaults pair. The fresh-reading verification before a
    switch (`AppState.swift:1230-1236`) checks the TARGET's resolved pair with the same eligibility function, in the
    mode (strict or relaxed) the plan was made in. `noteStayingPut` (`:1279-1291`) and the decision log lines
    (`:1200-1207, 1241-1243`) use the active account's leaveAt pair and name the window. `AutoSwitchRecord` gains `window`.

## 3. Feature B: priority numbers

- `Account.priority: Int?` (Swift `var`, optional), 1-99. Pure helpers next to `AccountOrder`: `sortedByPriority(_:,
  lastSet:)` (stable; the account set most recently first among equals), `settingPriority(_:of:in:) -> [Account]?` (nil
  for an unknown id or a value outside 1-99 other than nil), `numberedInOrder(_:)` (1..N; used by `setOrder` and a drag).
- `AccountOrder.fallback(from:)` uses the sorted order.
- Every path that appends or reorders accounts leaves the array sorted (sign-in, add-current, setOrder, drag,
  setPriority, load).
- **A priority number is never an account reference.** References stay id, email, label and position (the `#`
  column, `list_accounts` position). Priorities are shown as `P1` everywhere so they cannot be read as `#1`.

## 5. The Linux version

### 5.1 Shape

One background service owns everything that talks to Anthropic or writes a login; every face is a client of its socket.

| Piece | What it is | Runs as |
|---|---|---|
| `pixelswitchd` | Accounts, saved logins, switching Claude Code's login, usage and profile polling behind the usage guard, saved-login renewal, auto-switch, sign-in sessions, the updater, the control socket | systemd user service `pixelswitch.service` |
| `pixelswitch` | The CLI and `pixelswitch mcp`: same commands, flags, output and exit codes as the Mac CLI (`control.md` 3.x), plus section 4 | on demand |
| `pixelswitch-tray` | GNOME top-bar icon (StatusNotifierItem), label = active account's session %. Menu: each account in priority order (`P1 address · S 42% · W 61%`, active checked, a short form of its message under it if it has one), click to switch; Auto-switch on/off; Refresh; Settings; Sign in another account; Quit tray. Live via `events.subscribe` | GTK 3 process, XDG autostart |
| `pixelswitch-settings` | Accounts (per account: priority, Session and Weekly menus, Manual only, label, both windows with % and reset time, Fable %, "Updated N ago", the account's message in the Mac's exact sentences, Retry, Re-sign, Remove with confirmation), General (auto-switch, both defaults, strategy with the D6 line, Fable with its caption, early switching and hours, refresh interval), Sign in (start, both links with Open and Copy, code box, status), About (version, Update automatically, Check now, log path) | GTK 4 + libadwaita process |

Rules for the faces: they never send `usage.refresh` by themselves (not on start, open, re-exec or reconnect); only the
user's Refresh or Retry does. They never exec `pixelswitchd`; they start it only with
`systemctl --user start pixelswitch.service`.

`pixelswitchd` lifecycle:
- Takes an exclusive `fcntl.flock` on `~/.local/state/pixelswitch/daemon.lock` (path from `HOME` only) before reading
  any store or binding the socket, for its whole life; if held, it exits 0 with "already running" and touches nothing.
  Only while holding it may it unlink a stale socket. It writes the socket path it bound to
  `~/.local/state/pixelswitch/socket-path`.
- On SIGTERM or SIGINT it starts no new cycle, switch, renewal or sign-in, lets in-flight renewals finish their POST,
  ownership check and save (bounded by the request timeouts, at most 80 s), cancels a running sign-in as Cancel does,
  then exits 0.
- Calls `os.umask(0o077)` at start (every PixelSwitch process does) and removes `CLAUDE_CONFIG_DIR` and
  `CLAUDE_SECURESTORAGE_CONFIG_DIR` from the environment of every `claude` it runs; if its own environment sets either it
  logs a warning and `status` shows one line.
- The unit: `Restart=on-failure`, `RestartSec=120`, `StartLimitIntervalSec=3600`, `StartLimitBurst=4`,
  `KillMode=mixed`, `TimeoutStopSec=90`, `UMask=0077`. An automatic restart is the only thing that limits how often the
  unpersisted guard state is lost, so nothing restarts the daemon in a loop. (A test checks the unit file holds these.)

### 5.2 Paths and files (Linux)

- Claude Code's login: `~/.claude/.credentials.json` (top key `claudeAiOauth`; other top keys such as `mcpOAuth`
  preserved). Identity: `~/.claude.json` key `oauthAccount` (opaque object; read `accountUuid`, `emailAddress`).
  `CLAUDE_CONFIG_DIR` is not honoured, as on the Mac (`ClaudeCredentialsFile.swift:22-27`); the README says so.
- PixelSwitch: `~/.config/pixelswitch/settings.json` and `accounts.json`; saved logins
  `~/.local/share/pixelswitch/backups.json` in the Mac keychain item's shape `{uuid: {token, oauthAccount}}`; log
  `~/.local/state/pixelswitch/pixelswitch.log` (the Mac log's line format, no emails); socket
  `$XDG_RUNTIME_DIR/pixelswitch/control.sock`, fallback `~/.local/state/pixelswitch/control.sock`. Clients read
  `socket-path` first, then try `$XDG_RUNTIME_DIR/...`, `/run/user/<uid>/pixelswitch/control.sock`, the fallback, and run
  `systemctl --user start pixelswitch.service` once when none answers (unless `PIXELSWITCH_NO_LAUNCH=1`). Socket 0600 in a
  0700 directory, `SO_PEERCRED` uid check.
- **Every file PixelSwitch writes** (`.credentials.json`, `~/.claude.json`, `backups.json`, `settings.json`,
  `accounts.json`, state files) is written atomically: a temp file in the target's directory opened `O_CREAT|O_EXCL` at
  0600, written, fsync'd, `os.replace`d, then the directory fsync'd. A replaced file keeps its owner and never gets wider
  permissions than it had (0600 when new). A symlinked or hard-linked target is refused. Directories PixelSwitch creates
  are 0700. The log is opened 0600.
- Install: `~/.local/share/pixelswitch/app/<version>-<build>/` with a `current` symlink; `~/.local/bin/pixelswitch`;
  `~/.config/systemd/user/pixelswitch.service`; `~/.config/autostart/pixelswitch-tray.desktop`;
  `~/.local/share/applications/pixelswitch-settings.desktop`; icons under `~/.local/share/icons/hicolor/`. Every
  process puts `os.path.realpath` of its own package directory on `sys.path` at start, so a running process never loads
  another version's code.

### 5.3 Behaviour that must match the Mac exactly (cite the recon section when building it)

- **Switch** steps 0-10 (`credentials.md` section 3) with S1 = `~/.claude/.credentials.json` written per 5.2. Owner
  proof via `GET /api/oauth/profile` only; lineage may refuse, never prove.
- **Claude Code's refresh lock.** First confirm, read-only from the installed Claude Code on the laptop, the lock's
  path, holder record, touch interval and takeover rule (`credentials.md` 5.1), and record it in `linux/README.md`. If
  confirmed: take it BEFORE step 4's final read of the live credential, hold it through the merge read (step 5), the write
  and the read-back (step 6), release it in a `finally`. Under the lock re-read the live credential; if its
  `claudeAiOauth` differs from the proven one, re-prove once or skip the snapshot. Wait at most 35 s to take it (Claude
  Code's refresh timeout is 30 s), then fail the switch with nothing written ("Claude Code is renewing this login; try
  again in a minute."). Hold it at most 10 s, keep it touched as Claude Code does, write a holder record Claude Code reads
  as live, and never remove, break or take over a lock PixelSwitch did not create. If it cannot be confirmed: take no
  lock and say so in the README.
- **Re-read before write (both platforms, always, lock or not):** immediately before writing S1, re-read the live
  credential; if its `claudeAiOauth.accessToken` or `refreshToken` differs from what step 4 saved, do not write: repeat
  step 4 (with proof) once, else fail the switch with nothing written. Unit-test the compare.
- **Capture** of a login Claude Code refreshed (`credentials.md` 5.1), **saved-login renewal** (5.2, 5.3: endpoint
  `https://console.anthropic.com/v1/oauth/token`, the Mac's client id and body), every guard in section 6, D12, D20.
- **Renewal keeps `refreshTokenExpiresAt` honest (both platforms):** on success, if the response has a positive
  `refresh_token_expires_in`, set `claudeAiOauth.refreshTokenExpiresAt = now_ms + refresh_token_expires_in * 1000`; if
  it has none and the stored value is in the past, remove the key. Nothing else changes; `scopes` untouched. Unit tests
  for both cases. (Claude Code treats a past value as signed out; recon risk R7.)
- **Usage and profile** requests, headers, timeouts, polling schedule and round-robin, and every `UsageRequestGuard` rule
  and constant (`usage.md`); 401/403/429/5xx/offline handling and the user-facing sentences. Port the guard's unit tests.
- **Auto-switch cycle:** 300 s cooldown, verification with a fresh reading before committing, fall-through, the
  no-subscription rule, Manual only, staying-put logged once per change (`autoswitch.md`), with the 2.0 engine.
- **Sign-in** (`signin.md`): `claude auth login [--email]` on pipes with `BROWSER` pointed at a private capture helper;
  both links shown; nothing opens a browser unless the user presses Open (`Gio.AppInfo.launch_default_for_uri` or
  `xdg-open`). **Linux has no 10-second fallback** that lets Claude Code open a browser itself: if no automatic link
  arrives, the manual link and the code box are shown. Same limits and outcomes otherwise. Find `claude` via the
  `claude.binaryPath` setting, else `PATH` plus `~/.local/bin`, else `bash -lc 'command -v claude'`.
- **Control protocol**, framing, encoding rules, envelope, error kinds and texts, resolver, events, the 22 settings keys
  plus the two new ones (`control.md` sections 1, 2, 5). `launchAtLogin` maps to the tray autostart file;
  `updates.automatic` to the Linux updater.
- **How a running Claude Code notices a rewritten login:** confirm read-only from the installed Claude Code (stat mtime,
  inode, a watcher) and record it in `linux/README.md`; if it needs more than the atomic rename gives, the switch does it.

### 5.4 Updater (Linux)

- Checks `https://github.com/BespokeWoodcraftStudio/PixelSwitch/releases/latest/download/latest-linux.json` two minutes
  after start and every 6 hours; a 404 is "no update", quietly. JSON: `version`, `build`, `url`, `size`, `sha256`,
  `signature` (base64 Ed25519 over the tarball bytes).
- **Nothing in the feed is trusted until checked:** `version` is two whole numbers joined by a dot; `build` a whole
  number greater than the running build; `url` starts with
  `https://github.com/BespokeWoodcraftStudio/PixelSwitch/releases/download/v<version>/`; `size` at most 50 MB, and the
  download is cut off at `size`. Size, SHA-256 and signature are checked BEFORE anything is extracted (openssl 3
  `pkeyutl -verify -rawin`, else the bundled pure-Python RFC 8032 verifier from `release.md` appendix A; fail closed if
  neither works). Extract into a temp directory beside `app/` with `tarfile` `filter='data'`. The tarball carries a
  `VERSION` file (version and build) that must equal the feed's, with a build greater than the running one; only then
  rename the temp directory to `<version>-<build>`.
- **Self-check before the flip:** `python3 -I <new>/bin/pixelswitchd --self-check` (imports every module, reads
  settings, accounts and backups read-only, prints version and build, exits 0). Flip `current` only on exit 0 with a
  matching version, and only immediately before the restart.
- Restart only when no switch, sign-in, saved-login renewal or store write is in progress. Keep the previous version's
  directory; delete only versions older than it. The new daemon writes `~/.local/state/pixelswitch/good-<build>` after
  its first complete cycle. A small stdlib `ExecStartPre` script installed outside the versioned directories flips
  `current` back to the previous version when the current build has failed to start 3 times without writing its good
  marker. The tray re-executes itself when the daemon reports a new version.
- `updates.automatic` is on by default (as the Mac's since 1.4). Test hooks `PIXELSWITCH_TEST_RELEASE_BASE` and
  `PIXELSWITCH_TEST_PUBLIC_KEY` are honoured only in test mode (5.7). Unit tests: older build, mismatched VERSION, wrong
  url prefix, oversize, path traversal, a self-check failure, the rollback.

### 5.5 Install

`linux/install.sh`, published as the release asset `install-linux.sh`: `set -euo pipefail`; first checks Python >=
3.12, `gi.require_version` for Gtk 4.0, Adw 1, Gtk 3.0, Dbusmenu 0.4, and `org.kde.StatusNotifierWatcher` on the
session bus, refusing with one plain sentence naming what is missing (only a warning for the watcher: the service and
CLI still work). Fetches `latest-linux.json` and the tarball, verifies size, SHA-256 and the Ed25519 signature with
openssl (public key embedded; fails closed when openssl cannot verify Ed25519), installs per 5.2 for the current user,
enables and starts the service, starts the tray when a graphical session is present, and prints the next step
(`pixelswitch accounts add-current`, or Sign in from the tray). **Auto-switch stays off** after a first install (as on
the Mac), and the closing text says that on a machine where other tools use the same Claude Code login (the laptop's
CabDesign farm), switching changes their account too. `--uninstall` removes the app and keeps saved logins unless
`--purge`; `--from <tarball> [--signature <file>]` installs a local build (labelled unverified without a signature);
`--no-systemd` and `--no-autostart` exist for tests. No sudo, ever. The README states the first install trusts GitHub
over HTTPS and gives the two-step form: download `install-linux.sh` from the tag URL, compare its SHA-256 with the one in
the release notes, then run it.

## 6. Conformance vectors (the shared contract between the Swift and Python engines)

`Tests/conformance/autoswitch-vectors.json`, a list of cases:

```
{ name, now,
  settings: { strategy, watchFable, drainEarly, drainWithinHours, hysteresis (default 1),
              defaults: { base?, session?, weekly? }          // RAW stored values; absent = unset; 2.2 applies
  },
  accounts: [ { id, priority?, prioritySetOrder?, switchThreshold?, sessionThreshold?, weeklyThreshold?,
                switchable, unusable,
                usage?: { five_hour?: { utilization: number|null, resets_at? }, seven_day?: {...}, fable?: {...} } } ],
  active, activeSampledThisCycle,
  expect: { order: [ids after sortedByPriority],
            rules: { <id>: { session, weekly, manualOnly, leaveSession, leaveWeekly } },
            plan: null | { limit, trigger, window?, relaxed: bool, targets: [ids in order] } } }
```

The harness first sorts `accounts` with `sortedByPriority` (checking `expect.order`), passes every account except the
active one as candidates in that order, applies 2.2 to the raw values (checking `expect.rules`), then runs the plan
(checking `expect.plan`). Cases cover at least: the founder's example both directions (session 90 / weekly 50); equal
thresholds reproducing 1.9 decisions; each layer of the resolution chain; the 2.1 split (70 -> Default on one window);
Manual only active and as a candidate; Fable on the weekly rule, keepsFable with no Fable reading, strict Fable expiry
on the active side; early drain and no-subscription with split values; weekly overflow (rule 9) including the
ping-pong case it prevents and the case where overflow does not hold because one account has no weekly reading;
expired windows on both sides; a missing window; no reading at all; ranking ties under all three strategies; priority
gaps, ties (most recently set first) and unnumbered accounts; window values 0, -5, 0.4, 100.4. Neither lane edits this
file: a disagreement is reported to the orchestrator with the reasoning.
