## 18:46 PDT · WL-2026-09-25-001 · Design written: remote control, per-account thresholds, next-account strategy, sign-in links

**Type:** design · **Status:** wip

### What
Wrote the design for everything the founder asked for on 2026-09-24/25: a `pixelswitch` CLI plus MCP mode for AI remote control, per-account switch thresholds, a next-account strategy (most room / my order / resets soonest), and sign-in links with Open, Open in <browser> and Copy. Put it on a review page with the one open choice.

### Why
Brainstorming gate: architectural work needs a written spec the founder approves before any code. His answers (recorded verbatim in docs/decisions/2026-09-24-remote-control-answers.md) set: SSH-style access with no network listener, always on and everything allowed, both add paths, both CLI and MCP.

### How
- Read AutoSwitchEngine and AppState's evaluateAutoSwitch, loginNewAccount and reauthenticateAccount.
- Spiked `claude auth login` (2.1.280): started with BROWSER pointing at a capture script, cancelled after 8 s, credential fingerprint unchanged. Found two links: the printed one is the MANUAL flow (redirect platform.claude.com/oauth/code/callback, page shows a code, CLI reads `code#state` on stdin); the one handed to BROWSER is the AUTOMATIC flow (redirect http://localhost:<port>/callback, finishes by itself in any browser on this Mac). The opener runs `$BROWSER <url>` else `open <url>`.
- Spec: docs/superpowers/specs/2026-09-25-remote-control-and-auto-switch-design.md. Review page: docs/decisions/pixelswitch-design-review-2026-09-25.html (rendered 1920x1080 both themes, Copy tested).

### Outcome
Spec awaiting approval. Nothing built.

### Decisions (made without asking, stated in the spec)
- Priority order = the accounts list order itself, one order everywhere, set by drag in a new Settings → Accounts tab; "My order" always picks from the top.
- "Resets soonest" ranks by the weekly window (never the 5-hour one).
- Per-account threshold range 50–100 (100 = drain completely); global default slider widened to 50–100.
- Sign-in uses the automatic link for Open/Open in/Copy; manual link + code box as the other-device fallback; 15-minute timeout; 10-second fallback to the old default-browser behaviour if the CLI's output changes; `--email` pre-fill for re-auth.
- CLI shipped at Contents/Helpers/pixelswitch, installed by a Settings button as a ~/.local/bin link; user-only Unix socket with a peer-uid check; tokens never cross; every remote command logged. `remove` needs `--yes` (typo guard, not a permission).
- Action layer: AppController + throwing versions of AppState actions; SettingsStore takes side effects out of the views so CLI changes behave like GUI changes.

### Lessons
- The link `claude auth login` prints is NOT the one that finishes by itself; only the BROWSER link (localhost redirect) does. Copying the printed link would force a second copy/paste of a code.
- The founder-questions template styles links only inside cards; a link in the lede renders default blue, unreadable in dark mode.

### Follow-ups
1. Founder answers the review page (approve design; switch early a/b/c).
2. Then writing-plans, one plan per part: A auto-switch and B sign-in links in parallel lanes, then C remote control. Release as 1.2.
