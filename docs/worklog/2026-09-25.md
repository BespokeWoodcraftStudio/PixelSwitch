- The first CI build of the combined branch failed; that is fixed. A final whole-branch self-review then found and fixed two Important defects.

### Why
The founder wants an AI on another Mac to do anything he can do in PixelSwitch, over SSH (decisions in docs/decisions/2026-09-24-remote-control-answers.md). It must be always on, with everything allowed, and must never return a token.

### How
- Protocol: PixelSwitch/Control/ControlProtocol.swift, shared by the app and the tool.
- App side: ControlAPI (pure, tested against a fake app), then AppController, then AppState; SettingsStore owns every setting's side effect.
- Transport: ControlServer (socket) and ControlClient (tool side).
- Tool: PixelSwitchCLI/{CLIParser, CLIRunner, MCPServer, PixelSwitchCommand}.
- Tests: Tests/UnitTests/ControlTests.swift, run by the swiftc harness (no Xcode on this Mac). Tests/integration/remote-control.sh is a safe check against the real running app.

CI fix (commit 80942b8). Run 36216364642 failed: the `pixelswitch` target compiled the app's GeneratedAssetSymbols.swift.
- Cause: target `pixelswitch` and app `PixelSwitch` share one intermediates folder on the runner's case-insensitive disk (Release/pixelswitch.build is the same folder as Release/PixelSwitch.build). The tool read the app's SwiftFileList.
- Fix: renamed the target and module to PixelSwitchCLI. `productName: pixelswitch` keeps the file name. Without it, XcodeGen names the product reference after the target, and the copy into Contents/Helpers would look for a file that doesn't exist.
- New guard, scripts/check-target-names.sh: RED on the old spec, GREEN now. It runs in scripts/typecheck.sh and as a CI step before the build.
- Run 36216754622 then went green. The artifact was checked:
  - The helper is universal, with Identifier ai.pixelventures.pixelswitch.cli, the hardened runtime and team LM3P28DNVQ.
  - The app passes `codesign --verify --deep --strict`, and spctl accepts the app and the DMG as Notarized Developer ID.
  - The ticket is stapled.

Final self-review fixes (single lane, so no subagent reviewer):
1. commit 091af0d: a watcher that stops reading (e.g. a frozen SSH `pixelswitch watch`) blocked the main actor for up to 2 s on every event and was left with half a line. `ControlConnection.send` now closes a connection whose line cannot be written whole. `ControlServer` takes `writeTimeoutMilliseconds`, so the test uses 100 ms. Test "socket: a subscriber that stops reading is dropped at its first stalled write" went RED then GREEN.
2. commit da842a7: `CLIRunner.out` used print(). Over SSH stdout is a pipe, so events sat in stdio's 4 KB buffer: nothing appeared for dozens of events, and they were lost when watch was stopped. The integration script's watch check would have failed too. It now writes unbuffered through FileHandle. Test "cli: each line reaches a pipe at once" points stdout at a pipe; RED then GREEN.

### Outcome
- 509 of 509 unit tests pass; type-check OK for the app (70 files) and the CLI (6 files); the target-name guard passes.
- Final CI build 36217242179 on da842a7 was running when this was written. The DMG handed to the founder must come from this run, not 36216754622, which predates the two review fixes.
- The hand-check page is generated (docs/decisions/pixelswitch-hand-checks-2026-09-25.html, via scratchpad genChecks.py). It was rendered at 1920x1080 in light and dark, and its Copy button was tested. Not committed yet: it goes in with the DMG.

### Decisions & trade-offs
- The target is renamed; the product stays `pixelswitch`, so Contents/Helpers/pixelswitch, the CI codesign step and the ~/.local/bin link are unchanged.
- The stalled watcher is closed, not buffered. A client that stopped reading cannot be trusted with a partial line, and the only cost is one 2 s stall per stuck client.
- The DMG is handed over only after the review fixes, so one round of hand checks covers the code that ships.
- The plan and spec still name the target `pixelswitch`. They stay as the historical record; the Part C ledger has a ruling.

### Lessons / gotchas
- **On macOS CI (a case-insensitive disk), two Xcode targets must never have names or module names that differ only by case.** Their <target>.build folders and their <module>.SwiftFileList files are the same path. The symptom is a baffling "missing file" belonging to the other target. scripts/check-target-names.sh now refuses it.
- In XcodeGen, `PRODUCT_NAME` in settings does not rename the product file reference; the target-level `productName:` key does. Always check `path =` on the product's PBXFileReference after a rename.
- `xcodegen dump --type json --quiet` prints nothing. Leave `--quiet` off when piping the dump.
- In a CLI meant to be piped over SSH, never write streaming output with print(). Write straight to the file descriptor (or flush every line).
- Anything on the main actor that writes to a socket needs a bound and must drop the peer when it's exceeded; otherwise a single stuck client stalls the menu bar app.
