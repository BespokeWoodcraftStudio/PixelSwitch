### Decisions
- **NOT building a direct reset call (founder, 2026-11-19, option A, and "you absolutly do not execute a reset").** Anthropic's server offers resets only to claude.ai and Claude Code; every saved account answered "ineligible" to PixelSwitch, including beeco1@pixelventures.ai, which has a reset. A direct call would mean pretending to be one of those two. Do not add code (app, CLI, MCP, Linux) that calls the reset or grant endpoints to use a reset or that presents itself as claude.ai or Claude Code. A repo-wide test pins this. If the window cannot hold a claude.ai sign-in, the fallback is option B (open claude.ai/settings/usage in the browser), never a direct call.
- **NOT changing the User-Agent** (or any other header) to look like claude.ai or Claude Code, for the same reason: the server's gate is on which client is asking, and we will not disguise ours.
- A window per account with its own persistent web data store (not one shared sign-in) so a Limit resets click can never land on the wrong account.

### Lessons
- **The server's "surface" gate:** reset offers are decided by which client asks (claude.ai or Claude Code), not by the account or its token. The same token that sees an offer on claude.ai gets "ineligible" from PixelSwitch. Read the three limit-reset investigation files before touching this.
- **This Mac builds SwiftUI views** (Xcode 27.2); the old "cannot compile SwiftUI view files" line in CLAUDE.md was stale and is corrected.
- **`CardFooterRow` with `ViewThatFits` flickers if a live relative date (seconds) is inside it:** the width of the text changes every second so the chosen layout flips. Whole minutes, or a fixed-width text, keep it stable.
- `scripts/decisions/render-decision-page.cjs` still points at a missing `/Users/ahamade` Playwright path; this page used `scripts/hand-checks/render-hand-checks-2.2.cjs`, which looks in cabinet-designer's `node_modules` too.
