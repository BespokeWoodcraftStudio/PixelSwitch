## 17:27 PDT · WL-2026-10-24-001 · 2.0 started: recon and spec for separate session/weekly thresholds, priority numbers, Linux

**Type:** design · **Status:** wip · **Tags:** 2.0,linux,thresholds,priority

### What
Started PixelSwitch 2.0 on the founder's order of 2026-10-24: separate auto-switch thresholds for the 5-hour session and
the weekly window (example: session 90%, weekly 50%), priority numbers per account ("ahmed@gmail.com = 3,
ahmed@pixelventures.ai = 1"), and a version for Ubuntu tested on his laptop; then release so every client updates.
Seven read-only Sonnet recon reports and the build contract are committed on branch `release-2.0` (not main).

### Why
Recon first, because the Linux port must copy the Mac's login handling exactly (refresh-token rotation, the usage 429
guard) and the protocol change must not break shipped CLIs (they require protocolVersion == 2 exactly).

### How
- Recon: `docs/investigations/2026-10-24-linux-and-split-thresholds/recon/` (credentials, usage, autoswitch, control,
  signin, release, laptop).
- Spec: `docs/superpowers/specs/2026-10-24-2.0-spec.md`: decisions D1-D17 with reasons; feature, protocol, Linux,
  updater, CI, conformance-vector and acceptance sections.
- Opus spec review (three lenses) running before any build.

### Outcome
Spec committed (807ac61 on `release-2.0`). Nothing built yet. Next: fix the spec from the review, write the shared
conformance vectors, then two Sonnet build lanes (Mac, Linux core) in `.claude/worktrees/`.

### Decisions
- Priority is a stored number, not the list position (a typed number must stay the number typed); list kept sorted by it.
- Threshold layers, most specific wins; no data migration, so existing Macs behave as 1.9 until a window value is set.
- Linux is Python + PyGObject, no sudo; the tray registers itself over D-Bus because the AppIndicator typelib is missing.
- Protocol stays 2, all additions optional; new methods for new behaviour.
- PixelDirector is not touched (founder, 2026-10-24: another session is working in it).

### Lessons
- The CLI decodes the accounts list with `try?`: any new non-optional field makes a new CLI print "No accounts yet"
  against an old app. New wire fields must be optional `var`s.
- Recon found a real Mac bug (risk R4): Claude Code blanks a dead login on disk and capture can save the blank over a
  good saved login. Fixed in 2.0 by a blank-login guard (spec D12).

### Follow-ups
- Recon risks R2 (switch while the live token is expired skips the leaving-login save) and R3 (no use of Claude Code's
  refresh lock on the Mac) stay open on the Mac after 2.0; Linux takes the lock if its mechanism is confirmed.
