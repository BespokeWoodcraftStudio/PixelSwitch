## 17:27 PDT · WL-2026-10-24-001 · 2.0 started: recon and spec for separate session/weekly thresholds, priority numbers, Linux

**Type:** design · **Status:** wip · **Tags:** 2.0,linux,thresholds,priority

### What
Started PixelSwitch 2.0 on the founder's order of 2026-10-24: separate auto-switch thresholds for the 5-hour session and
the weekly window (example: session 90%, weekly 50%), priority numbers per account ("ahmed@gmail.com = 3,
ahmed@pixelventures.ai = 1"), and a version for Ubuntu tested on his laptop; then release so every client updates.
Seven read-only Sonnet recon reports and the build contract are committed on branch `release-2.0` (not main).

### Why
Recon first, because the Linux port must copy the Mac's login handling exactly (refresh-token rotation, the usage 429
guard) and the protocol change must not break shipped CLIs (they require protocolVersion == 2 exactly).

### How
- Recon: `docs/investigations/2026-10-24-linux-and-split-thresholds/recon/` (credentials, usage, autoswitch, control,
  signin, release, laptop).
- Spec: `docs/superpowers/specs/2026-10-24-2.0-spec.md`: decisions D1-D17 with reasons; feature, protocol, Linux,
  updater, CI, conformance-vector and acceptance sections.
- Opus spec review (three lenses) running before any build.

### Outcome
Spec committed (807ac61 on `release-2.0`). Nothing built yet. Next: fix the spec from the review, write the shared
conformance vectors, then two Sonnet build lanes (Mac, Linux core) in `.claude/worktrees/`.

### Decisions
- Priority is a stored number, not the list position (a typed number must stay the number typed); list kept sorted by it.
- Threshold layers, most specific wins; no data migration, so existing Macs behave as 1.9 until a window value is set.
- Linux is Python + PyGObject, no sudo; the tray registers itself over D-Bus because the AppIndicator typelib is missing.
- Protocol stays 2, all additions optional; new methods for new behaviour.
- PixelDirector is not touched (founder, 2026-10-24: another session is working in it).

### Lessons
- The CLI decodes the accounts list with `try?`: any new non-optional field makes a new CLI print "No accounts yet"
  against an old app. New wire fields must be optional `var`s.
- Recon found a real Mac bug (risk R4): Claude Code blanks a dead login on disk and capture can save the blank over a
  good saved login. Fixed in 2.0 by a blank-login guard (spec D12).

### Follow-ups
- Recon risks R2 (switch while the live token is expired skips the leaving-login save) and R3 (no use of Claude Code's
  refresh lock on the Mac) stay open on the Mac after 2.0; Linux takes the lock if its mechanism is confirmed.

## 23:09 PDT · WL-2026-10-24-002 · PixelSwitch 2.0 released: separate session/weekly limits, priority numbers, and a Linux version (installed on the laptop)

**Type:** feature · **Status:** done · **Tags:** 2.0,release,linux,thresholds,priority

### What
Released **v2.0 (build 31)** on 2026-10-25 06:01 UTC, Mac and Linux from one tag, on the founder's order of 2026-10-24
("different limits for the 5hr session and the weekly", "priority ... based on a number system ... ahmed@gmail.com = 3,
ahmed@pixelventures.ai = 1", "a version that works on Ubuntu", "push to production so all downstream clients get it").
- Mac: Session and Weekly defaults (50-100) and per-account Session/Weekly limits (1-100); priority numbers 1-99 shown as
  P1 (lists sorted by them; "My order" is now "Priority (lowest number first)"); weekly overflow (when no account under
  its weekly limit can take you, the session limit decides); CLI `accounts threshold --session/--weekly`,
  `accounts priority`, a Priority column; MCP `set_account_thresholds`, `set_account_priority` (20 tools); protocol stays 2.
- Login-safety fixes on the Mac: a blank login is never saved or written (D12); re-read before every write; renewal keeps
  refreshTokenExpiresAt honest; removing the active account really switches Claude Code (D20, with the disposable-login
  rule for a switch with no active account); a 429 is recorded even with no account.
- Linux (Ubuntu 24.04/26.04): Python daemon (systemd user service), CLI and MCP identical to the Mac's, GNOME tray
  (StatusNotifierItem over D-Bus, no sudo), libadwaita settings window, signed self-updates with rollback, user-only
  installer. Installed for real on the founder's laptop from the release.

### Why
The founder's three asks, shipped through Sparkle (Macs) and the new Linux updater. Recon first, because the Linux port
had to copy the Mac's login handling exactly (refresh-token rotation, Claude Code's locks, the 1.9 429 guard).

### How
Opus orchestrated; Sonnet built in lanes (V vectors, MA/MB Mac, LA/LB/LC Linux, fix lanes FA-FE, FL1-FL4), each in its own
`.claude/worktrees/` worktree with owned files; Opus reviewed every lane (multi-lens, read-only) and re-reviewed every
fix until zero P0/P1. 150 shared conformance cases run on both engines; a frozen 1.9 engine oracle proves equal-window
behaviour is unchanged (39,600 + 9,000 comparisons). Spec: `docs/superpowers/specs/2026-10-24-2.0-spec.md` (rev 4).
Every review and finding: `docs/investigations/2026-10-24-linux-and-split-thresholds/`.

### Outcome
- `scripts/verify-release.sh v2.0`: all Mac checks (Latest, feed 2.0/31, appcast length = DMG, EdDSA verified,
  notarized, stapled) and all Linux checks (assets, versions, size, SHA-256, Ed25519, installer hash in the notes) pass.
- Tests: Mac 1352/1352 (incl. 150/150 conformance and the 1.9 oracle); Linux 1670 on 3.14/3.12, CI green on Ubuntu
  24.04 and 26.04; scratch-HOME integration 94/94 on the Mac and the laptop.
- Laptop: 2.0 installed from the tag (installer SHA-256 31bdbeeb...47a0 checked), service active, account added (13%
  session / 11% weekly), auto-switch OFF, tray registered, log clean (0 401/429/errors), Claude Code's login files
  byte-identical before and after.
- Macs (founder's, Beeco): 1.9 at release time with automatic updates on; next Sparkle checks ~06:50 and ~07:16 UTC.

### Decisions
- Priority is a stored number (a typed 3 stays 3), lists sorted by it; drags renumber 1..N.
- Threshold layers with no data migration, so the Beeco Mac (98/98) behaves exactly as 1.9 (oracle-proven).
- Weekly overflow (D19) after the recheck proved the strict rule strands the founder's own 90/50 example.
- Protocol stays 2, everything additive; new methods for new behaviour.
- Linux has no sudo, no 10 s browser fallback, auto-switch off at install, English only, no cost dashboard (D15).
- linux-publish needs linux-test too (stricter than spec 5.6 as first written); Linux MCP texts reword five "Mac" phrases.
- Founder's four choices ship with defaults (decision page); answers that change behaviour ship as 2.1.

### Lessons
- This Mac cannot compile SwiftUI view files (macro plugin missing): a lane dropped `import SwiftUI` and only CI caught it.
  Every Mac view change needs a CI branch build before merge to main.
- `gh run watch ...; echo` exits 0 on failure: make the wait's exit status follow the run's conclusion, and read it.
- Polling CI every 20 s plus lanes' `gh` calls exhausted the account's 5,000/h API quota, which other sessions share.
  Poll every 120 s or more; lanes must not use the GitHub API.
- A lane's `brew install pygobject3` pulled in python@3.15 and made it the default `python3`; restored to 3.14. Lanes may
  not install anything on the founder's machines (now in the lanes rules).
- Ubuntu 24.04 reuses a freed inode at once and stamps directories coarsely: lock ownership must use exact values
  (birth time in ns, our own random-ns mtime), never a tolerance.
- Never remove a worktree another running lane reads (the vectors checkout had to be restored).
- Render tools with verbatim sample text can look like missing translations; check the real string path.
