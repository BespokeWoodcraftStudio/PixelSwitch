## 08:38 PDT · WL-2026-10-16-001 · 1.9: the 'API Rate Limited' banner was PixelSwitch resending refused logins; diagnosed, fixed, released and verified

**Type:** fix · **Status:** done · **Tags:** usage,429,oauth,release

### What
The founder (2026-10-16): "on my computer, I'm getting this API rate-limited message, because it's driving me crazy." Three of his five accounts (ahmed@pixelventures.ai, the active one; ahamade@gmail.com; ahmed@bespokewoodcraftstudio.com) showed "API Rate Limited. Try again later." every hour since 2026-10-16 04:08Z, and claude@pixelventures.ai had done the same hourly from 2026-10-13 to 10-15. Diagnosed, fixed and shipped as **1.9** (build 30) the same day.

### Why
Anthropic's `/api/oauth/usage` and `/api/oauth/profile` answer about the fourth refused (401) call on a login within an hour with 429 and Retry-After 3600 (all 49 measured values). PixelSwitch kept resending dead logins: the expired live login while Claude Code sat idle (usage poll plus the 5-minute `reconcileLiveLogin` profile lookup), and saved logins whose refresh grant the server had already refused, on every round-robin visit, forever. Every one of the 49 429s followed 401s on that account; a healthy login read 748 times with no 429, so volume was never the cause. Today's surge was PixelSwitch's round-robin polling the remaining dead logins every 5 to 15 minutes (not 20) whenever one was parked, set off by the 06:53Z auto-switch's extra cycle. The UI made it worse: the 401 path wiped the reading, the next 429 overwrote the honest "session expired" text, the park belonged to the account (not the token) so a re-sign stayed blank for up to about 65 minutes, and a dead account still looked switchable.

### How
- Read-only investigation workflow (5 Sonnet lanes: this Mac's logs, the code, other callers, public reports, the Beeco Mac; an Opus synthesis; 2 Opus skeptics). Nothing called the endpoint.
- One Sonnet builder in `.claude/worktrees/usage-429` (branch `fix/usage-429-dead-tokens`) from a written brief; two Opus reviewers (regression; replay of the real log history). Round 0 found one P1 (a no-token needs-reauth flag could latch onto a healthy live login), fixed in round 1; the Opus re-review passed with zero P0/P1.
- New pure `PixelSwitch/Services/UsageRequestGuard.swift` gates every usage and profile request: never resend a token that got a 401; renew an expired saved login first; leave an expired live login alone ("Waiting for Claude Code to renew this login"); 20 minutes' rest after any 401 or 429 whatever the account count; server-refused grant = `needsReauth` (persisted, not polled, not switchable); the park belongs to the token fingerprint, and `noteCredentialChanged(for:)` clears it on any token change. Honest messages in all five languages.
- Branch CI build (run 38924140452) verified with `scripts/verify-ci-artifact.sh`; fast-forwarded to main; `./scripts/release.sh 1.9`; release run 38924948392; `scripts/verify-release.sh v1.9` passed.

### Outcome
1.9 is published and verified (Latest, feed 1.9/30, EdDSA signature verified, notarized, stapled; the new strings ship in all five tables, "API Rate Limited" is gone). 706/706 unit tests (628 plus 78). Both Macs install it by themselves within about 6 hours. Before release, the founder had re-signed ahmed@pixelventures.ai and ahamade@gmail.com; all five accounts read normally from 14:48Z.

### Decisions
- Park deadlines are NOT persisted across relaunch: a stale park surviving a relaunch is worse than one extra request per account.
- The delegated `claude auth status` refresh is removed: 13 runs, 0 recoveries, and its retry resent the same dead token.
- `needsReauth` is set only on a server refusal (invalid_grant, rotationLost, belongsToAnotherAccount), never on the local same-grant guard (`BackupRefreshOutcome.localRefusal`).
- A saved login with no refresh token is flagged needs-reauth; kept on purpose (it cannot be renewed). Reasons for all of these: `docs/investigations/2026-10-16-usage-429.md`.

### Lessons
- A 429 with Retry-After 3600 here means "a refused login was sent too often", not "polled too much". Do not respond to it by polling less; stop sending refused tokens.
- "The server got stricter on 10-16" looked true from averages and was false: per-account gaps went from exactly 20 minutes to 5 to 15. Measure the gaps per account, not the hourly mean.
- `scripts/typecheck.sh` no longer works on this Mac (Swift 6.4 Command Line Tools lack the SwiftUIMacros plugin, and swiftc stops at `PixelSwitchApp.swift`, so later files are never checked; a planted error proved it). Use the reordered check in the investigation's scripts folder plus a CI branch build.
- Never run a diagnosis experiment that calls the endpoint with an expired token: it spends the quota and re-arms the one-hour block.
